## Phase 5 — Findings and fixes

### Fixed

**Q1-a — `SkeuWorkspacePill` painted itself with `Color.white`** (three call
sites: the chevron stroke, the pill's foreground, the dropdown rows). The
struct did not read `\.skeu` at all, which is why it reached for a literal.
This broke the design system's own acceptance test — "any screen must re-skin
correctly by changing only `.skeuTheme(...)`" — and CLAUDE.md lists
`hardcoded Color.white` on the reject-on-sight list. Now `skeu.ink` /
`skeu.inkMuted`.

**Q1-b — `Win95PinReplaceDialog` used `Color.black` for its scrim** (written
in this session). A scheme whose darkest tone is not black would have shown a
black veil over its own colours. Now `Win95.darkShadow`.

### Resolved by founder decision

**A1 — The light skeu palettes failed their own contrast requirement.**
Founder chose: light means light, text black (2026-08-16). Implemented — see
the "Light mode is light" commit. Cream now measures 10.9:1; the four derived
themes are lifted at their single base. Original analysis kept below.

`cream` is `ink: .white` on `canvas: #AA8360`. Measured: **3.42:1**.
`inkMuted: #F2E4D5` on the same canvas: **2.72:1**. `SkeuPalette.swift` itself
annotates `inkMuted` with "≥ 4.5:1 required", and the design system's
accessibility section repeats it. Primary text sits below the threshold for
secondary text.

This is NOT a bug in the sense of "someone made a mistake" — the whole look
was transcribed from a Figma frame that was dark, and the light variant kept
the same white-on-brown relationship at a lighter canvas. It reads as
intended, it just does not meet the contrast bar the project set for itself.

Three ways out, none of them a small edit:
1. Darken `ink` to a deep brown in the light palettes and keep the canvas.
   Correct by the numbers; changes the light theme's character completely.
2. Darken the canvas until white clears 4.5:1 (needs roughly #8A6A4C or
   darker). Keeps the white-on-brown look; makes "light" barely lighter
   than "dark".
3. Accept it and amend the design system to state the real target.
   Honest, but it is a real accessibility regression for anyone using it.

Affects all five themes' light variants, not just cream.

**Q7-a — the package stopped building for macOS**, and with it the whole test
suite. `PinnedTaskActivity` and `PinnedTaskIntents` guarded on
`canImport(ActivityKit)` / `canImport(AppIntents)`. Both modules ARE importable
on macOS — every type inside is marked unavailable instead — so the guard
compiled in and then failed on the protocol. `Package.swift` targets macOS for
the future Mac app, so `swift test` died before running a single test.
Narrowed to `#if os(iOS)`. **52 tests in 12 suites pass again.** Introduced
earlier the same day; caught here.

### Round 2 — findings

**Q6-a — dead code from today's own rewrites (fixed).** `SkeuSettingsView.G`
still carried `cardRadius`, `cardRim`, `cardPad`, `troughPad`, `pillPadV`,
`icon`, `pillSmall` and `circle` — all zero references since the outer cards
and the old option pills were replaced by `SkeuSegment` / `SkeuRowButton`.
Plus six computed vars (`pillSmallH`, `circleSize` in three structs each) and
two unused `pillH` copies. Removed.

**A2 — a photo cannot be deleted in the skeu look. REPORTED, not fixed.**
`PhotoViewer` (Win95) takes `onRemove` and calls `store.removePhoto`.
`SkeuPhotoViewer` takes only a close callback — `store.removePhoto` has
exactly one caller in the whole app, and it is the Win95 viewer. So a photo
attached in the skeu look can never be removed without switching design.
Fails C1 (parity). Not fixed here because WHERE the control goes and what it
looks like in that viewer is a design decision, not a mechanical one.

**A3 — FR-003's photo menu entries were never built, in either look.** The
spec asks for `Attach photo` / `Replace photo` / `Remove photo` in the row
menu. Neither menu has them; photos are added by the camera glyph in the
editing row instead, which post-dates the requirement. This is spec drift,
not a bug — except that it leaves A2 with no second route.

**Q3, Q8 — clean.** Every shadow resolves through the palette; the two
`SkeuCard` calls go via a local helper. The four store functions that write
without `commit()` are a read-only query, a private helper whose callers all
commit, and two debug seeders.
